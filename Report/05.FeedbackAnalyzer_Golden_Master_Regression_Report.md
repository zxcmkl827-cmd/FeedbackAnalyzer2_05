# Feedback Analyzer Golden Master 회귀 안전장치 구축 보고서

## 1. 보고서 개요

본 보고서는 Refactoring 시작 전 회귀 안전장치로 구축한 Golden Master Approval Test 작업 내용을 정리한다.

이번 작업의 목적은 `TextAnalyzer`의 출력 계약을 기준 파일로 고정하고, 이후 리팩터링 과정에서 출력 변화가 발생하면 테스트 실패로 즉시 감지하는 것이다.

## 3. Golden Master 기준 출력 전략

Golden Master 기준 출력은 UI 실행 결과가 아니라 `TextAnalyzer`의 분석 결과를 문자열로 직렬화한 값으로 정의했다.

기준 출력에는 다음 정보가 포함된다.

| 영역 | 내용 |
| --- | --- |
| Inputs | 테스트 시나리오 입력 피드백 8건 |
| Sentiment | 긍정, 중립, 부정 카운트 |
| Categories | 가격, 배송, 사용성, 서비스, 품질 카운트 |

현재 기준 파일의 핵심 결과는 다음과 같다.

```text
[Sentiment]
긍정=2
중립=3
부정=3

[Categories]
가격=1
배송=1
사용성=1
서비스=2
품질=1
```

`일반 문의 내용입니다.`는 `서비스` 카테고리 키워드인 `문의`에 매칭되므로 서비스 카운트는 `2`가 현재 승인된 동작이다.

## 4. Approval Test 구현

### 4.1 verify 메소드 적용

초기 구현은 수동으로 기준 파일 존재 여부를 확인하고 `EXPECT_EQ`로 문자열을 비교하는 방식이었다.

사용자 요청에 따라 approval test 비교 구간을 `ApprovalTest::Test::verify(...)` 호출 방식으로 변경했다. 내부적으로는 `ApprovalTests::Approvals::verify(...)`를 사용한다.

적용된 테스트 호출 형태는 다음과 같다.

```cpp
TEST(GoldenMasterTest, ApproveTextAnalyzerOutput) {
    const std::filesystem::path expectedPath = GOLDEN_MASTER_EXPECTED_PATH;
    ApprovalTest::Test::verify(buildGoldenMasterOutput(), expectedPath);
}
```

### 4.2 기준 파일명 고정

ApprovalTests.cpp의 기본 승인 파일명은 테스트명 기반으로 생성된다.

이번 요구사항은 `tests/golden_master_expected.txt`를 기준 파일로 보관하는 것이므로, `ApprovalNamer`를 구현해 approved/received 경로를 고정했다.

| 파일 유형 | 경로 |
| --- | --- |
| approved | `tests/golden_master_expected.txt` |
| received | `tests/golden_master_received.txt` |

테스트 성공 시 received 파일은 ApprovalTests.cpp가 정리하므로 저장소에는 기준 파일만 남는다.

### 4.3 기준 파일 없을 때 자동 생성

기준 파일이 없을 때는 `AutoApproveIfMissingReporter`를 사용해 ApprovalTests.cpp가 생성한 received 출력을 approved 파일로 자동 승인하도록 구성했다.

ApprovalTests.cpp 정책상 첫 auto-approve 실행은 "다음 실행부터 성공" 의미로 실패를 반환할 수 있다. 따라서 생성 스크립트는 `-Force` 실행 시 첫 실패 후 기준 파일이 생성되었는지 확인하고 테스트를 한 번 더 실행해 PASS를 검증한다.

## 5. 생성 스크립트

Golden Master 기준 파일 재생성 명령은 다음과 같다.

```powershell
powershell -ExecutionPolicy Bypass -File scripts\generate_golden_master.ps1 -Force
```

스크립트 동작 흐름은 다음과 같다.

1. `-Force` 지정 시 기존 `tests/golden_master_expected.txt` 삭제
2. 필요 시 CMake configure 수행
3. `sentiment_tests` 빌드
4. `GoldenMasterTest.ApproveTextAnalyzerOutput`만 실행
5. auto-approve 첫 실행 실패가 발생하면 한 번 더 실행해 PASS 확인

## 6. CMake 반영

`CMakeLists.txt`에는 ApprovalTests.cpp를 `FetchContent`로 연결했다.

주요 변경 사항은 다음과 같다.

| 항목 | 내용 |
| --- | --- |
| 의존성 추가 | `ApprovalTests.cpp` |
| 링크 대상 | `ApprovalTests::ApprovalTests` |

| 기준 파일 경로 매크로 | `GOLDEN_MASTER_EXPECTED_PATH` |

ApprovalTests.cpp 자체 테스트와 예제 빌드는 비활성화했다.
