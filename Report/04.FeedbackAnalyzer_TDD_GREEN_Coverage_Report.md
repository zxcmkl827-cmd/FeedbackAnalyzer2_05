## 6. Boundary/Domain 분리 상태 확인

현재 결함 수정 로직은 `TextAnalyzer.h`의 Domain 감정 판정과 `Constants.cpp`의 감정 키워드 데이터에 위치한다. 이번 결함 대응을 위해 Boundary 파일에 감정 분석 로직을 추가하지 않았다.

다만 기존 구조상 `main.cpp`에는 다음 책임이 함께 남아 있다.

- HTTP 라우팅
- HTML 렌더링 호출 및 응답 생성
- form body parsing
- CSV line parsing
- 세션 데이터 접근
- `TextAnalyzer`와 `Filters` 호출 orchestration
- CSV 다운로드 응답 생성

따라서 "Boundary에 로직이 남아 있지 않음"이라는 기준은 아직 충족하지 못한다. 현재 상태는 결함 목록 통과를 위한 GREEN 단계이며, Boundary/Control/Domain 구조 분리는 별도 REFACTOR 단계에서 다루는 것이 적절하다.

## 8. 후속 작업 제안

1. `main.cpp`의 form parsing, CSV parsing, 응답 생성, 유스케이스 orchestration을 Boundary/Control/Domain으로 분리한다.
2. `renderPage`, CSV 다운로드, upload/filter 라우팅에 대한 Boundary 테스트를 추가한다.
3. `TextAnalyzer` 구현을 헤더에서 `.cpp`로 이동하고 Domain 테스트 범위를 명확히 산정한다.
4. CMake에 coverage 전용 옵션 또는 preset을 추가해 `gcov/lcov` 측정을 반복 가능하게 만든다.
