# FeedbackAnalyzer 신규 기능 QA 종합 보고서

## 1. 작업 개요

| 항목 | 내용 |
| --- | --- |
| 프로젝트 | `FeedbackAnalyzer` |
| 언어/도구 | C++17, CMake, GoogleTest, CTest, ApprovalTest |
| 대상 기능 | CSV 결과 저장, 키워드 카운트/가중치 기반 감정 판단 |
| QA 관점 | Dual-Track UI(Boundary) + Logic(Domain) TDD |
| 최종 상태 | 전체 회귀 테스트 및 ApprovalTest 통과 |

이번 작업은 기존 FeedbackAnalyzer 코드에 신규 기능을 추가하고, 기능 테스트와 Approval Golden Master를 통해 회귀 안정성을 확보하는 것을 목표로 수행했다. 리팩토링 중심 작업이 아니라 기존 코드에 필요한 로직과 메서드를 최소 범위로 추가하는 방식으로 진행했다.

## 2. 요구사항 및 검토 결과

### 2.1 신규 기능

피드백 결과를 CSV 파일 형태로 저장하고, 파일명은 `FeedbackResult_[현재시간]` 형식을 따르도록 요구되었다.

검토 결과 기존 코드에는 `CsvExporter`, `/download` 라우트, `FeedbackController::downloadCsv()`가 존재했지만 다음 한계가 있었다.

- 다운로드 파일명이 `filtered_feedback.csv`로 고정되어 있었다.
- CSV 내용이 `text` 컬럼만 포함했다.
- 필터를 적용하지 않은 상태에서는 다운로드 대상 데이터가 비어 있을 수 있었다.
- 쉼표, 큰따옴표, 줄바꿈에 대한 CSV 이스케이프가 없었다.

### 2.2 변환 기능

감정 판단 방식을 단순 키워드 포함 방식에서 모든 키워드 카운트 비교 및 가중치 기반 판단으로 변경하는 요구가 있었다.

검토 결과 기존 `TextAnalyzer`는 부정/긍정 키워드를 우선순위대로 포함 여부만 검사했고, 카운트와 가중치를 반영하지 않았다. 또한 중립 문맥 예외는 이미 존재했으므로 신규 판정 방식에서도 유지해야 했다.

## 3. 테스트 설계 및 RED 결과

요구사항을 기준으로 신규 기능 5개, 변환 기능 5개의 테스트를 설계했다. 테스트 코드는 `tests/sentiment_tests.cpp`에 추가했다.

| 구분 | 테스트 수 | 초기 결과 | 주요 검증 |
| --- | ---: | --- | --- |
| CSV 결과 저장 | 5 | 4 FAIL, 1 PASS | 파일명, 분석 컬럼, 필터 전 다운로드, 이스케이프, BOM |
| 가중치 감정 판단 | 5 | 3 FAIL, 2 PASS | 카운트 비교, 가중치, 동점 중립, 중립 문맥 |
| 합계 | 10 | 7 FAIL, 3 PASS | 신규 요구사항 결함 재현 |

초기 실패는 요구사항과 기존 구현의 차이를 명확히 보여주었다.

- `CSV_SAVE_01`: `FeedbackResult_YYYYMMDD_HHMMSS.csv` 파일명 미지원
- `CSV_SAVE_02`: `sentiment`, `category` 분석 컬럼 미지원
- `CSV_SAVE_03`: 필터 미적용 상태 다운로드 데이터 미흡
- `CSV_SAVE_04`: CSV 특수문자 이스케이프 미지원
- `WEIGHTED_SENTIMENT_01`: 긍정 키워드 다수 조건 미반영
- `WEIGHTED_SENTIMENT_03`: 가중치 판단 미반영
- `WEIGHTED_SENTIMENT_04`: 동점 시 중립 정책 미반영

## 4. 구현 내용

### 4.1 CSV 결과 저장

`CsvExporter.cpp`를 확장해 CSV 출력 계약을 보강했다.

- UTF-8 BOM 유지
- `text,sentiment,category` 헤더 추가
- 피드백별 감정/카테고리 컬럼 출력
- 쉼표, 큰따옴표, 줄바꿈 포함 필드 이스케이프

`FeedbackServer.cpp`에는 다운로드 파일명 생성 로직을 추가했다.

```text
FeedbackResult_YYYYMMDD_HHMMSS.csv
```

`FeedbackController.cpp`는 필터 결과가 있으면 필터 결과를, 없으면 현재 세션 피드백을 CSV로 내보내도록 보강했다.

### 4.2 키워드 카운트/가중치 기반 감정 판단

`TextAnalyzer.cpp`의 감정 판단을 점수 비교 방식으로 변경했다.

- 긍정 키워드 점수 계산
- 부정 키워드 점수 계산
- 일부 강한 긍정 표현에 가중치 부여
- 긍정/부정 점수 동점 시 중립 반환
- 중립 문맥 예외 우선 적용 유지

`Filters.cpp`도 필터 결과와 분석 결과의 방향성이 크게 어긋나지 않도록 점수 기반 판정으로 보강했다.

## 5. ApprovalTest 확장

기존 ApprovalTest는 유지하고, 신규 기능 전용 Golden Master를 별도로 추가했다.

| 항목 | 내용 |
| --- | --- |
| 기존 테스트 | `GoldenMasterTest.ApproveTextAnalyzerOutput` 유지 |
| 신규 테스트 | `GoldenMasterTest.ApproveNewFeatureOutput` 추가 |
| 승인 파일 | `tests/new_feature_golden_master_expected.txt` |
| 실행 방식 | `ApprovalTest::Test::verify(...)` 사용 |

신규 Golden Master는 다음 계약을 고정한다.

- 키워드 카운트 기반 긍정/부정 판정
- 가중치 기반 긍정 판정
- 동점 시 중립 판정
- 중립 문맥 우선 판정
- CSV UTF-8 BOM 표시 계약
- CSV 헤더 및 분석 컬럼 계약
- CSV 특수문자 이스케이프 계약

## 6. 테스트 및 커버리지 결과

### 6.1 전체 테스트 결과

| 검증 항목 | 결과 |
| --- | ---: |
| 전체 CTest | 72/72 PASS |
| 신규 기능 테스트 | 10/10 PASS |
| ApprovalTest | 2/2 PASS |
| 테스트 통과율 | 100% |
| 릴리스 차단 결함 | 0건 |

주요 검증 명령:

```text
cmake --build build
ctest --test-dir build --output-on-failure
cmake --build build-gcov --target sentiment_tests
ctest --test-dir build-gcov --output-on-failure
```

### 6.2 gcov/lcov 커버리지

최신 `build-gcov` 실행 후 핵심 테스트 대상 소스 기준 커버리지는 다음과 같다.

| 파일 | Line Coverage | Function Coverage |
| --- | ---: | ---: |
| `Constants.cpp` | 100% | 100% |
| `CsvExporter.cpp` | 98.1% | 100% |
| `Feedback.h` | 100% | 100% |
| `TextAnalyzer.cpp` | 95.5% | 100% |
| 합계 | 97.3% | 100% |

목표 대비 핵심 Domain/Data 영역은 충족했다. 다만 전체 App 및 Boundary/Control 레이어는 아직 테스트 타깃에 충분히 포함되지 않아 별도 보강이 필요하다.

| 영역 | 목표 | 현재 평가 |
| --- | ---: | --- |
| 핵심 Domain/Data 라인 커버리지 | 95% 이상 | 충족 |
| 핵심 함수 커버리지 | 90% 이상 | 충족 |
| Branch Coverage | 90% 목표 | lcov branch data 추가 설정 필요 |
| 전체 App/Boundary 커버리지 | 85~90% 목표 | 추가 테스트 필요 |

## 7. 결함 관리 및 패턴 분석

결함 관리는 `Docs/feature_defect_report.md`에 정리했다. Severity와 ItemType을 조합해 결함을 분류하고, 재현/기대/실제/원인/수정/검증 템플릿을 정의했다.

이번 작업에서 확인된 주요 결함 패턴은 다음과 같다.

| 패턴 | 사례 | 대응 |
| --- | --- | --- |
| Data/CSV 계약 누락 | 파일명, 분석 컬럼, 이스케이프 누락 | CSV 테스트 및 ApprovalTest로 고정 |
| Domain 판단 방식 한계 | 단순 포함/우선순위 방식 | 점수 비교 및 가중치 적용 |
| 부분 문자열 오탐 | `불편합니다` 내부 `편합니다` 매칭 | 좁은 보정 적용 |
| Boundary 회귀 보호 부족 | Controller/Server 직접 테스트 부족 | 다음 단계 개선 항목으로 분리 |

Critical 결함은 발견되지 않았고, 신규 요구사항 미충족 항목은 Major 수준으로 판단했다.

## 9. 개선 필요 단계

다음 단계에서는 Boundary/Control 품질 보강이 우선이다.

1. `FeedbackController` 유스케이스 테스트 추가
2. `FeedbackServer` 다운로드 헤더 및 content-type 테스트 전략 수립
3. `CsvParser`, `FormParser`, `HtmlRenderer` Boundary 계약 테스트 추가
4. `Filters`와 `TextAnalyzer`의 감정 판단 중복 축소
5. branch coverage 활성화 및 CI 커버리지 리포트 자동화
6. `build`, `build-gcov`, `coverage.*.info` 산출물 관리 정책 정리

Cursor AI는 요구사항 분석, 테스트 설계, 실패 재현, 기능 구현, ApprovalTest 추가, 문서화까지 QA 흐름을 연속적으로 수행하는 데 효과가 있었다.

| 항목 | Before | After | 효과 |
| --- | ---: | ---: | --- |
| 전체 테스트 수 | 61 | 72 | +11개 |
| ApprovalTest 수 | 1 | 2 | +1개 |

정성적으로는 CSV 출력 계약, 감정 판단 경계 조건, Golden Master 승인 기준처럼 수동 검토에서 누락되기 쉬운 항목을 빠르게 테스트로 고정한 점이 가장 큰 효과였다.

## 11. 최종 결론

신규 CSV 결과 저장 기능과 키워드 카운트/가중치 기반 감정 판단 기능은 현재 테스트 기준으로 안정화되었다. 전체 CTest 72개와 ApprovalTest 2개가 모두 통과했으며, 핵심 기능 소스의 gcov/lcov 커버리지 역시 목표를 충족했다.

남은 리스크는 전체 앱 관점의 Boundary/Control 테스트 부족이다. 다음 레거시 개선 단계에서는 HTTP 라우트, Controller 흐름, HTML 렌더링, CSV 파싱을 별도 테스트 타깃과 ApprovalTest로 확장해 릴리스 품질 기준을 더 높이는 것이 필요하다.
