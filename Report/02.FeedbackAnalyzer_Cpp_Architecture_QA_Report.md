## 2. 핵심 결론

| 구분 | 결론 |
|---|---|
| 요구사항 관점 | 피드백 입력, CSV 업로드, 키워드 분류, 감정 분석, 필터링, 시각화, CSV 다운로드가 핵심 기능이다. 문자열 매칭과 CSV/HTML 출력 경계가 주요 결함 발생 지점이다. |

## 3. C++ 구현 관점 요구사항 재정리

| 구분 | 요구사항 | C++17 구현 관점 | QA 확인 포인트 |
|---|---|---|---|
| 피드백 텍스트 입력 | 사용자가 웹 화면에서 피드백 텍스트를 입력할 수 있어야 한다. | HTTP 요청 body/form field를 `std::string`으로 수집하고, 빈 문자열/공백 문자열/개행 포함 문자열을 구분한다. | 빈 입력, 공백 입력, 여러 줄 입력, 긴 입력이 서버 오류 없이 처리되는지 확인한다. |
| CSV 업로드 | `text` 컬럼이 포함된 CSV 파일을 업로드할 수 있어야 한다. | CSV 파서는 헤더명 `text`를 기준으로 컬럼을 찾고 행 단위로 피드백을 추출해야 한다. | `text` 컬럼 누락, 빈 파일, 빈 행, 쉼표/따옴표/개행 포함 텍스트를 확인한다. |
| 키워드 기반 분류 | 피드백 텍스트에 포함된 키워드로 카테고리를 분류해야 한다. | `std::string::find` 또는 토큰 기반 matcher를 사용하되 부분 문자열 매칭 정책을 명확히 한다. | 여러 카테고리가 동시에 매칭될 때 우선순위 또는 다중 분류 정책이 일관적인지 확인한다. |
| 감정 분석 | 피드백을 긍정/부정/중립으로 분류해야 한다. | `enum class Sentiment { Positive, Negative, Neutral }`처럼 타입 안정적인 표현을 사용한다. | 긍정+부정 동시 포함, 키워드 없음, 중립 필터 동작을 검증한다. |
| 필터링/검색 | 감정 또는 키워드 기준으로 분석 결과를 필터링할 수 있어야 한다. | 원본 데이터와 필터 결과를 분리하고 `FilterCriteria`로 조건을 전달한다. | 조건 없음, 존재하지 않는 키워드, 중복 필터 적용, 중립 필터 오류를 확인한다. |
| 결과 시각화 | 감정 분석 비율과 분류 결과를 화면에 표시해야 한다. | 도메인 계산 결과와 HTML 렌더링을 분리하고, 통계 계산은 순수 함수로 테스트 가능하게 둔다. | 전체 0건일 때 divide-by-zero 없이 0건 상태로 표시되는지 확인한다. |
| CSV 다운로드 | 분석 결과를 CSV로 다운로드할 수 있어야 한다. | CSV exporter에서 헤더, UTF-8, field escaping, 줄바꿈 정책을 고정한다. | 쉼표, 따옴표, 개행, 한글이 포함된 결과가 깨지지 않는지 확인한다. |
| 로그 표시 | warning, error 등 level별 로그 표시를 제어할 수 있어야 한다. | `std::cout`/`std::cerr` 직접 호출 대신 `Logger` 인터페이스와 `LogLevel` enum을 사용한다. | 레벨별 표시/숨김, 오류 메시지의 내부 정보 노출 여부를 확인한다. |
| Trend 시각화 | 테스트 CSV 데이터를 기반으로 추세를 볼 수 있어야 한다. | 날짜/순서 필드를 파싱하고 집계 결과를 별도 모델로 표현한다. | 날짜 누락, 정렬되지 않은 데이터, 동일 날짜 중복 집계를 확인한다. |
| File DB 규칙 관리 | 감정 분석 필터 규칙을 파일 기반 DB로 관리해야 한다. | 규칙 로딩, 검증, 캐싱, 실패 정책을 `RuleRepository`로 분리한다. | 규칙 파일 없음, 빈 규칙, 중복 규칙, 잘못된 인코딩을 확인한다. |

## 4. 문자열 비교/분기 주의점

| 항목 | 주의점 | 권장 기준 | 테스트 관점 |
|---|---|---|---|
| `std::string::find` | `find()` 결과 위치 `0`은 정상 발견이다. boolean처럼 사용하면 맨 앞 키워드를 놓칠 수 있다. | 항상 `text.find(keyword) != std::string::npos`로 판정한다. | 키워드가 문자열 맨 앞에 있는 케이스를 포함한다. |
| 문자열 `==` 비교 | 감정값, 카테고리명, 헤더명을 문자열로 직접 비교하면 오타와 대소문자 차이에 취약하다. | 내부 로직은 `enum class`, 외부 입출력 경계에서만 문자열 변환을 사용한다. | `"중립"`, `"neutral"`, `"Neutral"`, 빈 문자열 입력 정책을 검증한다. |
| 부분 문자열 매칭 | 단순 포함 검색은 의도하지 않은 단어 일부까지 매칭할 수 있다. | 단순 키워드 포함인지 토큰 단위 매칭인지 요구사항을 명확히 한다. | 부분 일치, 완전 일치, 복합 문장 테스트를 분리한다. |
| 한글/UTF-8 | `std::string::size()`는 문자 수가 아니라 바이트 수이다. | 길이 제한 기준이 바이트인지 문자 수인지 구분한다. | 한글, 영문, 숫자, 특수문자 혼합 입력을 검증한다. |
| 중복 키워드 로직 | 분석과 필터가 서로 다른 matcher를 쓰면 결과가 달라진다. | 공통 `KeywordMatcher`와 공통 규칙 저장소를 사용한다. | 분석 결과와 필터 결과가 같은 기준인지 회귀 테스트로 고정한다. |
| 분기 우선순위 | 긍정/부정 또는 여러 카테고리 동시 매칭 시 순서에 따라 결과가 달라진다. | 우선순위 기반 단일 결과인지 다중 결과인지 정책을 명시한다. | 긍정+부정, 배송+가격 동시 포함 케이스를 테스트한다. |

## 5. 예외 및 경계값 조건

| 구분 | 조건 | 기대 동작 | 구현 주의점 |
|---|---|---|---|
| 빈 텍스트 | `""` | 중립 또는 입력 오류 중 하나로 일관 처리한다. | Domain 정책과 Boundary 입력 검증 정책을 분리한다. |
| 공백 텍스트 | `"   \t\n"` | 빈 텍스트와 동일 정책으로 처리한다. | trim 후 빈 문자열인지 판단한다. |
| 매우 긴 텍스트 | 수만 자 이상 | 서버가 크래시하지 않고 제한 초과 또는 정상 분석 결과를 반환한다. | 최대 입력 크기와 메모리 복사 정책이 필요하다. |
| 개행 포함 텍스트 | 여러 줄 피드백 | 원본 개행은 보존하고 분석은 전체 텍스트 기준으로 수행한다. | HTML 렌더링과 CSV escaping을 분리한다. |
| 특수문자 포함 | 쉼표, 따옴표, `<script>` | 분석은 가능해야 하며 출력 시 HTML/CSV escaping을 적용한다. | XSS 방지와 CSV escaping은 Boundary 책임이다. |
| CSV 헤더 누락 | `text` 컬럼 없음 | 파싱 실패와 사용자 오류 메시지를 반환한다. | 첫 번째 컬럼 가정 대신 헤더 기반 파싱을 사용한다. |
| CSV 빈 파일 | 0바이트 또는 헤더만 존재 | 0건 결과 또는 명확한 오류를 반환한다. | 0건 통계에서 divide-by-zero를 방지한다. |
| 규칙 파일 없음 | File DB 규칙 누락 | 초기화 실패 또는 기본 규칙 사용 여부를 명확히 한다. | 조용한 fallback은 운영 장애 분석을 어렵게 한다. |
| 전역 상태 | 세션/필터 결과가 전역 변수에 저장됨 | 요청 간 데이터가 섞이지 않아야 한다. | 테스트 간 상태 초기화 또는 인스턴스 상태 객체가 필요하다. |
| 예외 처리 | 파싱, 파일, 렌더링 중 예외 | 안정적인 오류 응답을 반환하고 내부 상태를 보존한다. | 구체 예외와 오류 타입을 사용한다. |

## 6. SOLID / Code Smell 분석

## 7. Magic Number / Magic String 상수화 대상

| 대상 | 현재 위치 | 상수화 필요성 | 권장 이름 예시 |
|---|---|---|---|
| 서버 포트 `8080`, host `"0.0.0.0"` | `main.cpp` | 실행 환경별 변경 가능성이 높다. | `AppConfig::defaultPort`, `AppConfig::defaultHost` |
| MIME type `"text/html; charset=UTF-8"`, `"text/csv; charset=UTF-8"` | `main.cpp` | 응답 생성 경로마다 반복되어 오타 가능성이 있다. | `ContentType::htmlUtf8`, `ContentType::csvUtf8` |
| 파일명 `"filtered_feedback.csv"` | `main.cpp` | 다운로드 정책과 테스트 계약에 해당한다. | `DownloadConfig::filteredFeedbackFileName` |
| CSV 헤더 `"text"` | `main.cpp`, README 요구사항 | CSV 입력/출력 계약의 핵심 값이다. | `CsvColumns::text` |
| 감정 문자열 `"전체"`, `"긍정"`, `"중립"`, `"부정"` | `main.cpp`, `TextAnalyzer`, `Filters`, `Constants` | 도메인 분기에 직접 사용되어 오타가 버그가 된다. | `enum class Sentiment`, `FilterOption::all` |
| 카테고리 문자열 `"배송"`, `"품질"`, `"가격"`, `"서비스"`, `"사용성"` | `Constants`, `UIComponents` | UI와 분석 규칙의 중복 source가 된다. | `enum class CategoryId`, `CategoryRule::displayName` |
| 카테고리 내부 key `"main"` | `TextAnalyzer`, `Filters`, `Constants` | 특별한 의미를 가진 문자열이지만 타입으로 표현되지 않는다. | `CategoryRule::primaryKeywords` |

## 8. C++17 스타일 개선 방향 요약

1. `enum class Sentiment`, `enum class CategoryId`를 도입해 문자열 기반 분기를 도메인 타입 기반 분기로 바꾼다.
2. `SentimentClassifier`, `CategoryClassifier`, `KeywordMatcher`를 추출해 분석과 필터가 동일한 전략을 공유하게 한다.
3. 키워드와 카테고리는 `CategoryRule`/`SentimentRule` 테이블로 관리하고 UI 필터 옵션도 이 테이블에서 생성한다.
4. `main.cpp`는 composition root로 축소하고 라우팅, 렌더링, CSV, 분석, 상태 저장을 별도 클래스로 분리한다.
5. 요청 처리 결과는 `std::variant<SuccessPage, WarningPage, ErrorPage>` 또는 명시적 `Result` 타입으로 표현해 오류 흐름을 테스트 가능하게 만든다.
6. `std::map<std::string, int>` 대신 `SentimentSummary`, `CategorySummary` 같은 의미 있는 결과 타입을 사용한다.
7. 전역 mutable 상태를 제거하고 `AppContext` 또는 의존성 주입된 store를 사용해 테스트 격리와 동시성 위험을 낮춘다.
8. CSV 입력/출력, HTML 출력은 각각 `CsvParser`, `CsvExporter`, `HtmlRenderer`로 분리하고 Google Test 및 Approval Test로 계약을 고정한다.

## 9. Google Test 기준 테스트 시나리오

1. `TextAnalyzer`는 빈 문자열 입력을 중립 또는 정책상 입력 오류로 일관 처리한다.
2. `TextAnalyzer`는 공백과 개행만 있는 입력을 빈 문자열과 동일하게 처리한다.
3. `TextAnalyzer`는 긍정 키워드가 포함된 피드백을 긍정으로 분류한다.
4. `TextAnalyzer`는 부정 키워드가 포함된 피드백을 부정으로 분류한다.
5. `TextAnalyzer`는 키워드가 없는 피드백을 중립으로 분류한다.
6. `TextAnalyzer`는 키워드가 문자열 맨 앞에 있을 때도 `find() != npos` 기준으로 정상 탐지한다.
7. `TextAnalyzer`는 긍정과 부정 키워드가 동시에 포함된 입력을 명시된 우선순위 정책대로 분류한다.
8. `CategoryClassifier`는 배송/가격/품질/서비스/사용성 키워드를 정책대로 분류한다.
9. `CategoryClassifier`는 여러 카테고리 키워드가 동시에 포함된 입력을 단일 또는 다중 분류 정책대로 처리한다.
10. `KeywordMatcher`는 키워드가 문자열 첫 위치에 있을 때 true를 반환한다.
11. `KeywordMatcher`는 빈 키워드 목록을 전달받아도 안정적으로 false 또는 정책상 오류를 반환한다.
12. `Filters`는 긍정/부정/중립 감정 필터를 각각 올바르게 적용한다.
13. `Filters`는 존재하지 않는 감정 문자열 입력을 오류 또는 빈 결과로 일관 처리한다.
14. `Filters`는 분석 로직과 동일한 키워드 매칭 기준을 사용한다.
15. `CsvParser`는 `text` 헤더가 있는 정상 CSV에서 모든 피드백 텍스트를 추출한다.
16. `CsvParser`는 `text` 헤더가 없을 때 명확한 실패 결과를 반환한다.
17. `CsvParser`는 빈 파일 또는 헤더만 있는 파일을 크래시 없이 처리한다.
18. `CsvParser`는 쉼표가 포함된 quoted field를 하나의 텍스트 값으로 파싱한다.
19. `CsvExporter`는 분석 결과를 고정된 헤더 순서로 출력한다.
20. `CsvExporter`는 쉼표, 따옴표, 개행이 포함된 텍스트를 CSV 규칙에 맞게 escaping한다.
21. `StatisticsCalculator`는 총 0건일 때 비율 계산에서 0으로 나누지 않는다.
22. `StatisticsCalculator`는 긍정/중립/부정 건수 합계가 전체 피드백 수와 일치하도록 계산한다.
23. `HtmlRenderer` 또는 Boundary 계층은 사용자 텍스트의 HTML 특수문자를 escaping한다.
24. `HtmlRenderer`는 빈 분석 결과를 0건 상태로 렌더링한다.
25. `Session` 또는 상태 객체는 테스트 간 상태가 누적되지 않도록 초기화 가능해야 한다.
26. `Logger`는 warning/error 레벨 설정에 따라 출력 대상을 제어한다.
27. `RuleRepository`는 규칙 파일 없음, 빈 규칙, 중복 규칙을 예측 가능한 결과로 처리한다.
28. `TrendAnalyzer`는 날짜별 피드백 수를 집계하고 정렬되지 않은 입력을 날짜순으로 반환한다.
29. HTTP 라우팅 테스트는 루트 경로, 피드백 제출, CSV 업로드 실패 응답을 확인한다.
30. Approval Test는 HTML, CSV, JSON 출력 계약이 의도치 않게 변경되지 않았는지 검증한다.
31. 회귀 테스트는 기존 오류 항목인 중립 감정 필터가 올바르게 동작하는지 별도 케이스로 고정한다.
