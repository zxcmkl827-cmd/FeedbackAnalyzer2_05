# Feedback Analyzer QA 테스트 및 결함 보고서

## 1. 보고서 개요

본 보고서는 `README.md`, `project_purpose.md` 기반으로 도출한 테스트 계획, GoogleTest 기반 감정 분석 테스트 작성, CTest 실행 결과, RED 단계 결함 목록 문서화 결과를 정리한다.

대상 프로젝트는 C++17, CMake, GoogleTest, CTest 기반의 고객 피드백 분석 웹 애플리케이션이며, 핵심 검증 대상은 `TextAnalyzer::sent()`의 긍정/부정/중립 감정 분석 동작이다.

## 3. 테스트 설계 요약

### 3.1 선택한 핵심 기능

텍스트 피드백 입력 기반 감정 분석 및 키워드 분류

### 3.2 기준 샘플 예제

| 구분 | 입력 | 기대 감정 | 기대 카테고리 |
| --- | --- | --- | --- |
| 정상 입력 | `배송이 너무 늦어요. 화가 납니다.` | 부정 | 배송 |
| 경계값 입력 | `배송` | 중립 | 배송 |

이 기능은 요구사항의 핵심 기능인 텍스트 입력, 키워드 기반 분류, 감정 분석을 동시에 검증할 수 있다. 또한 문장형 정상 입력과 최소 키워드만 포함한 경계값 입력을 함께 다룰 수 있어 테스트 플랜의 기준 사례로 적합하다.

## 4. GoogleTest/CTest 구성 결과

### 4.1 CMake 구성 변경

`CMakeLists.txt`에 다음 테스트 구성을 추가했다.

- `include(CTest)`로 CTest 활성화
- `find_package(GTest QUIET)` 및 `FetchContent` 기반 GoogleTest 연동
- `sentiment_tests` 테스트 실행 파일 추가
- `gtest_discover_tests(sentiment_tests)`로 CTest 자동 등록
- MSVC 환경의 한글 UTF-8 리터럴 빌드를 위한 `/utf-8` 옵션 추가

### 4.2 테스트 코드 작성 기준

- GoogleTest 사용
- Given-When-Then 주석 구조 적용
- 각 테스트에 기대 감정 결과 명시
- 테스트 이름은 `test_[기대결과]_[번호]` 형식 사용
- 테스트 통과를 위한 별도 헬퍼 메서드 작성 없음
- 제품 메서드 수정 없이 기존 `TextAnalyzer::sent()`만 호출

## 5. 테스트 실행 결과

### 5.1 빌드 결과

다음 명령으로 빌드가 성공함을 확인했다.

```powershell
cmake -S . -B build
cmake --build build
```

빌드 중 기존 `Logger.h`의 `localtime` 관련 MSVC 경고가 존재하지만, 감정 분석 테스트 추가와 직접 관련된 빌드 실패는 없다.

### 5.2 CTest 결과

다음 명령으로 테스트를 실행했다.

```powershell
ctest --test-dir build --output-on-failure
```

| 구분 | 테스트 수 | 결과 |
| --- | ---: | --- |
| 기존 정상 감정 테스트 | 30 | Pass |
| RED 단계 실패 재현 테스트 | 30 | Fail |
| 전체 | 60 | 30 Pass / 30 Fail |

현재 실패 상태는 의도된 RED 단계 결과이며, 제품 메서드 수정/추가 없이 유지했다.

## 7. 결함 위치 및 근본 원인

### 7.1 결함 위치

| 위치 | 결함 내용 |
| --- | --- |
| `src/cpp/Constants.cpp` | 긍정/부정 감정 키워드 사전의 표현 범위가 부족함 |
| `src/cpp/TextAnalyzer.h` | `containsAny()`가 단순 부분 문자열 포함 여부만 확인함 |
| `src/cpp/TextAnalyzer.h` | `sent()`가 중립 문맥 예외 없이 긍정 후 부정 순서로 감정을 확정함 |

### 7.2 근본 원인

감정 분석 로직이 키워드 포함 여부만 기준으로 동작한다. 이로 인해 감정 키워드 사전에 없는 실제 긍정/부정 표현은 중립으로 누락되고, UI 용어나 정책명처럼 감정이 아닌 문맥에 포함된 키워드는 긍정/부정으로 오탐된다.

## 8. 결함 심각도 분류

모든 RED 단계 결함은 `Critical`로 분류했다.

| Severity | 적용 대상 | 근거 |
| --- | --- | --- |
| Critical | `DEF-001` ~ `DEF-030` | 감정 분석 결과가 기대 감정과 완전히 다른 타입으로 산출됨 |
| Major | 해당 없음 | 현재 결함은 경계값 오차가 아니라 감정 타입 자체의 오분류임 |
| Minor | 해당 없음 | 출력 포맷 불일치가 아님 |
| Info | 해당 없음 | 코드 스타일/주석 문제가 아님 |

## 9. 최소 수정 방향 제안

실제 제품 코드는 수정하지 않았다. GREEN 전환 시 다음 방향의 최소 변경을 우선 검토한다.

- `Constants::SENTIMENT_KEYWORDS`에 누락된 긍정/부정 표현을 보강한다.
- `TextAnalyzer::sent()`의 기존 `if-else` 체인은 유지한다.
- 중립 문맥 예외 목록을 먼저 판정해 UI 용어, 정책명, 문서명 오탐을 줄인다.
- `Feedback` 등 기본 데이터 구조체는 변경하지 않는다.
- RED 테스트 30건이 GREEN으로 전환되는지 `ctest`로 확인한다.

## 10. README 반영 내역

`README.md`의 `5. 기능 개선 및 회귀 보호` 아래에 `RED 단계 To-Do 리스트 결함 목록`을 추가했다.

추가된 To-Do는 다음 결함 묶음을 추적한다.

- 긍정 의미 표현이 중립으로 분류되는 결함 10건: `DEF-001` ~ `DEF-010`
- 부정 의미 표현이 중립으로 분류되는 결함 10건: `DEF-011` ~ `DEF-020`
- 중립 문맥이 긍정 또는 부정으로 오탐되는 결함 10건: `DEF-021` ~ `DEF-030`
- `TextAnalyzer::sent()`의 단순 부분 문자열 매칭 오탐 방지
- `Constants::SENTIMENT_KEYWORDS`의 긍정/부정 표현 누락 보강

## 11. 후속 권장 작업

1. RED 단계 결함 30건에 대해 최소 수정안을 적용한다.
2. `cmake -S . -B build && cmake --build build`로 빌드 정상 여부를 확인한다.
3. `ctest --test-dir build --output-on-failure`로 60개 테스트 GREEN 여부를 확인한다.
4. 감정 분석 규칙 변경 후 Approval Test 대상인 HTML/CSV/JSON 출력 계약 영향도를 검토한다.
5. gcov/lcov 기반으로 Domain 95% 이상, Boundary 85% 이상 커버리지 목표 달성 여부를 측정한다.
