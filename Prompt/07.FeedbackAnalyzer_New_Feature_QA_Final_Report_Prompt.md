## CSV 결과 저장 기능
현재 CSV 관련 코드는 이미 있습니다.

- `CsvParser`: 업로드 CSV를 `Feedback` 목록으로 변환
- `CsvExporter`: `Feedback` 목록을 CSV 문자열로 변환
- `FeedbackServer`: `/download`에서 CSV 다운로드 응답 제공
- `FeedbackController::downloadCsv()`: `app_.filteredFeedbacks()`를 CSV로 변환

다만 요구사항의 “피드백 결과 CSV 파일 형태로 저장”과는 차이가 있습니다.

현재 다운로드는 `filtered_feedback.csv`라는 고정 파일명이며, 내용도 분석 결과가 아니라 `text` 컬럼만 포함한 피드백 원문입니다. 또한 실제 서버 파일로 저장하는 구조가 아니라 HTTP 다운로드 응답입니다.

```36:38:src/cpp/FeedbackServer.cpp
server_.Get("/download", [this](const httplib::Request&, httplib::Response& res) {
    res.set_header("Content-Disposition", "attachment; filename=\"filtered_feedback.csv\"");
    res.set_content(controller_.downloadCsv(), "text/csv; charset=UTF-8");
});
```

따라서 `FeedbackResult_[현재시간]` 파일명은 **대응 가능**합니다. 위치는 `FeedbackServer`의 `Content-Disposition` 생성부가 가장 직접적인 변경 지점입니다. 단, Windows 파일명에서는 `:`가 부적합하므로 `FeedbackResult_20260522_131900.csv` 같은 안전한 포맷이 좋습니다.

추가로 현재 구조에는 중요한 제약이 있습니다. `downloadCsv()`가 `filteredFeedbacks()`만 사용하므로, 사용자가 분석만 하고 필터를 적용하지 않은 상태에서 다운로드하면 빈 CSV가 내려갈 가능성이 있습니다.

```95:97:src/cpp/FeedbackController.cpp
std::string FeedbackController::downloadCsv() const {
    return CsvExporter::exportFeedbacks(app_.filteredFeedbacks());
}
```

결론: **파일명 변경은 쉽게 가능**, 하지만 “분석 결과 CSV”를 의미한다면 `CsvExporter`가 원문뿐 아니라 감정/카테고리/집계 결과를 출력하도록 모델 또는 DTO가 필요합니다.

## 감정 판단 방식 변경
현재 감정 판단은 “단순 포함 여부 + 우선순위” 방식입니다.

```47:58:src/cpp/TextAnalyzer.cpp
std::string TextAnalyzer::classifySentiment(const std::string& text) {
    if (isNeutralContext(text)) {
        return u8"중립";
    }

    for (const auto& sentiment : sentimentPriority()) {
        if (containsAny(text, Constants::SENTIMENT_KEYWORDS[sentiment])) {
            return sentiment;
        }
    }

    return u8"중립";
}
```

즉, 현재는 키워드 개수를 세지 않습니다. 부정 키워드가 하나라도 있으면 긍정보다 먼저 부정으로 판단합니다. “모든 키워드 카운트 비교 + 가중치 적용”으로 바꾸려면 `containsAny()` 중심 구조를 `countMatches()` 또는 `scoreSentiment()` 계열로 바꾸면 됩니다.

현재 코드로도 변경 자체는 가능하지만, 주의점이 있습니다.

- `Constants::SENTIMENT_KEYWORDS`에 중복 키워드가 존재합니다. 카운트/가중치 방식으로 바꾸면 중복 항목이 점수를 과대 계산할 수 있습니다.
- `TextAnalyzer`와 `Filters`가 서로 다른 감정 키워드/우선순위를 가지고 있습니다. 분석 결과와 필터 결과가 달라질 수 있으므로 감정 판단 로직은 하나로 통합하는 편이 안전합니다.
- 현재 `sent()`의 반환값은 `map<string, int>`로 “최종 감정별 개수”만 표현합니다. 가중치 점수, 매칭 키워드 수, 판단 근거까지 CSV에 담으려면 별도의 결과 타입이 필요합니다.
- 중립 판단 정책을 정해야 합니다. 예: 긍정 점수와 부정 점수가 같으면 중립, 둘 다 0이면 중립, 중립 문맥은 우선 차단할지 또는 별도 가중치로 계산할지.

## 종합 판단
기능 추가 대응 가능성은 **중간 이상**입니다. 빌드 구조, C++17, CMake, GoogleTest/ApprovalTest 기반은 이미 준비되어 있고 CSV/분석/HTTP Boundary도 분리되어 있습니다.

다만 바로 기능을 얹기보다는 다음 순서가 적절합니다.

1. “CSV 결과”의 의미를 확정: 원문 목록인지, 필터 결과인지, 감정/카테고리 집계인지, 피드백별 분석 결과인지 결정
2. 감정 판단 로직을 `TextAnalyzer` 중심으로 단일화
3. 키워드 중복 제거 또는 중복 허용 정책 결정
4. 가중치 설정 구조 정의: 코드 상수, 설정 파일, 카테고리별/키워드별 weight
5. CSV 출력 계약을 ApprovalTest로 고정

이번 검토에서는 코드 작성이나 테스트 실행은 하지 않았습니다.
