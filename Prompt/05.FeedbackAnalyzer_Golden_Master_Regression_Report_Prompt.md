요청하신 Golden Master 기준 파일과 생성 스크립트를 기존 테스트 구조에 맞춰 추가하겠습니다. 먼저 CMake와 테스트 파일 구성을 확인해 어떤 출력이 회귀 기준으로 적합한지 파악하겠습니다.

현재 테스트는 `sentiment_tests` 하나에 집중되어 있고, Golden Master 파일은 아직 없습니다. 감정 분석의 공개 출력 문자열을 고정하는 별도 테스트와 기준 파일 생성 스크립트를 추가하는 방향으로 진행하겠습니다.

기준 출력은 특정 UI 런타임 출력보다 안정적인 `TextAnalyzer`의 문자열화된 분석 결과로 잡겠습니다. 테스트는 파일이 없을 때 승인 기준을 만들고, 이후에는 같은 문자열을 엄격 비교하며 실패 시 줄 단위 diff를 출력하게 만들겠습니다.

이제 `CMakeLists.txt`에 Golden Master 테스트 소스를 연결하고, `tests/golden_master_tests.cpp`, `tests/golden_master_expected.txt`, `scripts/generate_golden_master.ps1`를 추가하겠습니다. 스크립트는 기준 파일을 지운 뒤 해당 approval 테스트를 실행해서 “파일 없음 → 현재 출력 승인” 경로로 재생성하도록 만들겠습니다.

파일 추가는 끝났고, 이제 실제 빌드/테스트로 기준 파일과 approval 비교 경로가 맞는지 확인하겠습니다. 기존 `build` 디렉터리를 사용해 `sentiment_tests`만 빌드한 뒤 Golden Master 테스트를 실행합니다.

첫 실행에서 두 가지를 확인했습니다. Windows 편집 파일의 CRLF와 테스트 출력의 LF가 달라 실패했고, `일반 문의`가 서비스 카테고리 키워드(`문의`)에 잡혀 서비스 카운트가 2가 되는 것이 실제 동작이었습니다. 기준 비교는 LF로 정규화하고 기준 파일의 실제 카운트를 반영하겠습니다.

PowerShell 환경이 `&&` 체이닝을 지원하지 않아 명령 구문만 실패했습니다. 같은 작업을 PowerShell 호환 구문으로 다시 실행하겠습니다.

Approval 테스트는 통과했습니다. 마지막으로 생성 스크립트의 `-Force` 경로도 확인해, 기준 파일 삭제 후 테스트가 자동으로 기준 파일을 재생성하는지 검증하겠습니다.

생성 스크립트 검증까지 통과했습니다. 전체 `sentiment_tests` 묶음에서도 새 테스트가 기존 테스트와 함께 문제없이 실행되는지 한 번 더 확인하겠습니다.

완료했습니다. `TextAnalyzer` 출력 기반 Golden Master를 추가했고, 기준 파일이 없으면 자동 생성하고 있으면 actual/expected를 비교해 diff와 함께 실패하도록 구현했습니다.

요청하신 대로 Golden Master 테스트의 approval 비교 부분을 `ApprovalTest::Test::verify` 기반으로 바꾸겠습니다. 먼저 현재 프로젝트에 ApprovalTests 헤더/패키지가 이미 있는지와 기존 테스트 코드를 확인하겠습니다.

현재 코드에는 수동 approve 로직만 있고 ApprovalTests 라이브러리는 아직 연결되어 있지 않습니다. `verify` API 형태와 CMake 연결 방식을 맞추기 위해 ApprovalTests 문서/패키지 구성을 확인한 뒤 테스트 파일만 그 패턴으로 교체하겠습니다.

Context7 문서 조회는 월간 쿼터 초과로 사용할 수 없었습니다. 대신 현재 코드베이스 상태와 공개 API 사용 패턴에 맞춰 `ApprovalTests.cpp`를 FetchContent로 연결하고 `ApprovalTests::Approvals::verify(...)` 호출로 테스트를 단순화하겠습니다.

이제 수동 `EXPECT_EQ`/diff 로직을 제거하고, 실제 비교는 ApprovalTests의 `verify` 호출이 담당하도록 바꾸겠습니다. `tests/golden_master_expected.txt`라는 기존 기준 파일명을 유지하기 위해 고정 경로 namer를 붙이고, 요청하신 `ApprovalTest::Test::verify(...)` 호출 형태로 감싸겠습니다.

수정은 반영했습니다. 이제 CMake가 ApprovalTests.cpp를 가져와 빌드할 수 있는지 확인하고, Golden Master 테스트와 전체 CTest를 다시 실행하겠습니다.

`verify` 기반 실행까지는 연결됐지만, 기존 기준 파일과 새 received 파일이 줄 끝 차이로 불일치 처리되고 있습니다. 기준 파일을 현재 `verify` 출력과 같은 LF 형태로 재생성한 뒤 다시 확인하겠습니다.

ApprovalTests가 received 파일을 Windows 텍스트 형식으로 쓰기 때문에 기존 LF 기준 파일과 바이트 단위로 달랐습니다. 수동 파일 생성 대신 `AutoApproveIfMissingReporter`를 `verify` 옵션에 연결해, 기준 파일이 없을 때 ApprovalTests가 생성한 received를 그대로 승인하도록 조정했습니다.

ApprovalTests의 auto-approve 동작은 첫 실행에서 기준 파일을 만들지만, 라이브러리 정책상 그 첫 실행은 실패로 보고합니다. 생성 스크립트는 `-Force` 재생성 시 이 첫 실패를 허용하고 즉시 한 번 더 실행해 통과를 확인하도록 보완하겠습니다.

요청대로 approval 테스트 부분을 `ApprovalTest::Test::verify(...)` 호출 방식으로 다시 구성했습니다.

변경 내용:
- `tests/golden_master_tests.cpp`
  - 수동 `EXPECT_EQ`/diff 비교 로직 제거
  - `ApprovalTests.hpp` 사용
  - `ApprovalTest::Test::verify(buildGoldenMasterOutput(), expectedPath)` 형태로 변경
  - 내부적으로 `ApprovalTests::Approvals::verify(...)`와 고정 파일명 namer 사용
- `CMakeLists.txt`
  - `ApprovalTests.cpp`를 `FetchContent`로 연결
  - `sentiment_tests`에 `ApprovalTests::ApprovalTests` 링크
- `scripts/generate_golden_master.ps1`
  - `-Force` 재생성 시 ApprovalTests의 첫 auto-approve 실패 후 한 번 더 실행해 통과 확인
