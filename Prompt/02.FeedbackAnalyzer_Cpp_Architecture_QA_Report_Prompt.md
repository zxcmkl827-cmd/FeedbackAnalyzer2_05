요청하신 산출물은 `docs/code_quality_report.md`로 저장하겠습니다. 먼저 실제 C++ 소스 구조와 주요 구현 파일을 읽어 SRP/OCP 위반, 코드 스멜, C++17 개선 포인트를 근거 중심으로 정리하겠습니다.

소스 탐색 결과 테스트 대상이 될 구현은 대부분 `src/cpp`에 모여 있고, 특히 `main.cpp`, `TextAnalyzer`, `Filters`, `Constants`, `Session` 쪽에 설계 리스크가 집중되어 있습니다. 이제 주요 파일을 직접 확인해 보고서에 들어갈 근거를 구체화하겠습니다.

확인해보니 `main.cpp`가 라우팅, HTML 렌더링, CSV 파싱, 상태 갱신, 다운로드까지 함께 담당하고 있고, `TextAnalyzer`와 `Filters`에는 키워드 판정 로직이 중복되어 있습니다. 이 근거를 표 형태로 압축해 보고서를 작성하겠습니다.

`docs/code_quality_report.md`를 새로 만들고, 우선순위는 `1`이 가장 먼저 처리해야 할 항목이라는 기준으로 정리하겠습니다. 각 행은 실제 파일/함수 근거와 영향, C++17식 개선 방향을 함께 담겠습니다.

완료했습니다. 기존 C++ 코드를 SOLID/Code Smell 관점에서 분석해 `docs/code_quality_report.md`로 저장했습니다.

보고서에는 요청하신 형식대로 `문제점 | 위반 원칙/스멜 | 영향 | 개선 방향 | 우선순위` 표를 포함했고, 추가로 Magic Number/String 상수화 대상과 C++17 개선 방향 요약, 리팩토링 우선순위 1~5를 정리했습니다.

검증: `docs/code_quality_report.md`에 대한 linter 오류는 없습니다. 코드 변경은 문서 추가만 했기 때문에 빌드/테스트는 실행하지 않았습니다.
