# Feedback Analyzer 요구사항 분석

## 1. C++ 구현 관점 요구사항 재정리

| 구분 | 요구사항 | C++17 구현 관점 | QA 확인 포인트 |
|---|---|---|---|
| 피드백 텍스트 입력 | 사용자가 웹 화면에서 피드백 텍스트를 입력할 수 있어야 한다. | HTTP 요청 본문 또는 form field에서 `std::string`으로 텍스트를 수집하고, 빈 문자열/공백 문자열/개행 포함 문자열을 구분한다. | 빈 입력, 공백 입력, 여러 줄 입력, 긴 입력이 서버 오류 없이 처리되는지 확인한다. |
| CSV 업로드 | `text` 컬럼이 포함된 CSV 파일을 업로드할 수 있어야 한다. | CSV 파서는 헤더명 `text`를 기준으로 컬럼을 찾고, 행 단위로 피드백 텍스트를 추출한다. 파일 I/O 예외와 잘못된 CSV 형식을 분리 처리한다. | `text` 컬럼 누락, 빈 파일, 빈 행, 쉼표/따옴표 포함 텍스트, 한글 텍스트 처리 여부를 확인한다. |
| 키워드 기반 분류 | 피드백 텍스트에 포함된 키워드로 카테고리를 분류해야 한다. | `std::string::find` 또는 정규화된 토큰 비교를 사용하되, 대소문자/공백/중복 키워드/부분 문자열 매칭 기준을 명확히 한다. | 동일 텍스트가 여러 카테고리에 매칭될 때 우선순위 또는 다중 분류 정책이 일관적인지 확인한다. |
| 감정 분석 | 피드백을 긍정/부정/중립으로 분류해야 한다. | 긍정/부정 키워드 매칭 결과를 바탕으로 `enum class Sentiment { Positive, Negative, Neutral }`처럼 타입 안정적으로 표현한다. | 긍정과 부정 키워드가 동시에 포함된 경우, 키워드가 없는 경우, 중립 필터가 올바르게 동작하는지 확인한다. |
| 필터링 및 검색 | 감정 또는 키워드 기준으로 분석 결과를 필터링할 수 있어야 한다. | 원본 데이터와 필터 결과를 분리하고, 필터 조건은 값 객체 또는 명시적 파라미터로 전달한다. 전역 mutable 상태 의존을 피한다. | 필터 초기화, 중복 필터 적용, 조건 없음, 존재하지 않는 키워드 검색 결과를 확인한다. |
| 결과 시각화 | 감정 분석 비율과 분류 결과를 화면에 표시해야 한다. | Domain 결과를 HTML 렌더링 문자열과 분리하고, 수치 계산은 순수 함수로 테스트 가능하게 둔다. | 전체 건수 0건일 때 백분율 계산, 반올림, 합계 100% 근접 여부를 확인한다. |
| CSV 다운로드 | 분석 결과를 CSV로 다운로드할 수 있어야 한다. | 출력 CSV는 헤더, 필드 escaping, 줄바꿈 처리를 고정된 계약으로 관리한다. | 쉼표, 따옴표, 개행, 한글이 포함된 결과가 깨지지 않고 재입력 가능한지 확인한다. |
| 로그 표시 | 로그를 warning, error 등 level별로 제어할 수 있어야 한다. | `std::cout`/`std::cerr` 직접 호출 대신 Logger 인터페이스와 로그 레벨 enum을 사용한다. | 로그 레벨별 표시/숨김, 오류 상황에서 사용자 화면에 과도한 내부 정보가 노출되지 않는지 확인한다. |
| Trend 시각화 | 테스트 CSV 데이터를 기반으로 추세를 볼 수 있어야 한다. | 날짜 또는 순서 필드를 파싱하고 집계 결과를 별도 모델로 표현한다. | 날짜 누락, 정렬되지 않은 데이터, 동일 날짜 중복 데이터 집계가 일관적인지 확인한다. |
| File DB 기반 규칙 관리 | 감정 분석 필터 규칙을 파일 기반 DB로 관리해야 한다. | 규칙 로딩, 검증, 캐싱, 실패 시 오류 반환 정책을 분리한다. | 규칙 파일 없음, 빈 규칙, 중복 규칙, 잘못된 인코딩, 런타임 갱신 정책을 확인한다. |

## 2. 문자열 비교 및 분기 시 주의점

| 항목 | 주의점 | 권장 기준 | 테스트 관점 |
|---|---|---|---|
| `std::string::find` 결과 판정 | `find()`는 위치값을 반환하며, 미발견은 `std::string::npos`이다. 위치 0은 정상 발견이므로 boolean처럼 사용하면 오류가 난다. | `text.find(keyword) != std::string::npos` 형태로만 판정한다. | 키워드가 문자열 맨 앞에 있는 케이스를 반드시 포함한다. |
| `==` 직접 비교 | 감정값, 카테고리명, 헤더명을 문자열로 직접 비교하면 오타와 대소문자 차이에 취약하다. | 내부 로직은 `enum class`, 외부 입출력 경계에서만 문자열 변환을 사용한다. | `"중립"`, `"neutral"`, `"Neutral"`, 빈 문자열 입력의 처리 정책을 검증한다. |
| 부분 문자열 매칭 | `"불만"`이 포함되면 부정으로 볼 수 있지만, 의도하지 않은 단어 일부도 매칭될 수 있다. | 요구사항이 단순 키워드 포함인지, 토큰 단위 매칭인지 명확히 정한다. | 부분 일치, 완전 일치, 복합 문장 테스트를 분리한다. |
| 대소문자 처리 | 영어 키워드가 추가되면 `find()`는 대소문자를 구분한다. | 비교 전에 동일한 locale/규칙으로 정규화하거나, 규칙 파일에 대소문자 정책을 명시한다. | `"Delay"`, `"delay"`, `"DELAY"`가 같은 결과인지 확인한다. |
| 공백과 개행 | 수동 입력은 여러 줄, 앞뒤 공백, 탭을 포함할 수 있다. | trim 대상은 검색어/필터값으로 한정하고, 원본 피드백 텍스트는 보존한다. | `" 배송 "`, `"\n배송 지연"` 입력이 기대대로 분류되는지 확인한다. |
| 한글 문자열 | UTF-8 환경에서 `std::string::size()`는 문자 수가 아니라 바이트 수이다. | 길이 제한은 바이트 기준인지 문자 기준인지 명확히 하고, UI 표시와 저장 정책을 분리한다. | 한글, 영문, 숫자, 특수문자 혼합 입력을 검증한다. |
| 중복 키워드 | `TextAnalyzer`와 `Filters`에 같은 contains 로직이 중복되면 결과가 달라질 수 있다. | 키워드 매칭 함수는 하나의 도메인 서비스 또는 유틸리티로 통합한다. | 분석 결과와 필터 결과가 같은 기준을 쓰는지 회귀 테스트로 고정한다. |
| 분기 우선순위 | 긍정/부정/중립, 다중 카테고리 매칭 시 순서에 따라 결과가 달라질 수 있다. | 우선순위 기반 단일 결과인지, 다중 결과인지 정책을 명시한다. | 긍정+부정 동시 포함, 배송+가격 동시 포함 케이스를 포함한다. |

## 3. 예외 및 경계값 조건

| 구분 | 조건 | 기대 동작 | 구현 주의점 |
|---|---|---|---|
| 빈 텍스트 | `""` | 감정은 중립 또는 입력 오류 중 하나로 일관 처리한다. | Domain 정책과 Boundary 입력 검증 정책을 분리한다. |
| 공백 텍스트 | `"   \t\n"` | 빈 텍스트와 동일 정책으로 처리한다. | trim 후 빈 문자열인지 판단한다. |
| 매우 긴 텍스트 | 수만 자 이상의 입력 | 서버가 크래시하지 않고 제한 초과 또는 정상 분석 결과를 반환한다. | 메모리 복사 최소화, 최대 입력 크기 정책이 필요하다. |
| 개행 포함 텍스트 | 여러 줄 피드백 | 원본 개행을 보존하면서 분석은 전체 텍스트 기준으로 수행한다. | HTML 렌더링과 CSV 출력 escaping을 분리한다. |
| 특수문자 포함 | 쉼표, 따옴표, `<script>` 등 | 분석은 가능해야 하며, 출력 시 HTML/CSV escaping을 적용한다. | XSS 방지와 CSV escaping은 Boundary 책임으로 둔다. |
| 키워드 없음 | 어떤 규칙에도 매칭되지 않음 | 카테고리 미분류 또는 기타, 감정 중립으로 처리한다. | null/빈 문자열 대신 명시적 enum 값을 사용한다. |
| 다중 키워드 | 여러 카테고리/감정 키워드 동시 포함 | 우선순위 또는 다중 분류 정책에 따라 결정한다. | 순회 순서에 의존하는 암묵 정책을 피한다. |
| CSV 파일 없음 | 업로드 요청에 파일 누락 | 사용자에게 입력 오류를 반환한다. | 파일 I/O 예외와 HTTP 400 계열 오류를 구분한다. |
| CSV 헤더 누락 | `text` 컬럼 없음 | 파싱 실패로 처리하고 오류 메시지를 반환한다. | 헤더 비교 기준의 대소문자/공백 정책을 정한다. |
| CSV 빈 파일 | 0바이트 또는 헤더만 존재 | 분석 결과 0건 또는 오류 중 정책에 맞게 처리한다. | 0건 통계에서 0으로 나누지 않는다. |
| 잘못된 CSV 행 | 따옴표 불일치, 컬럼 수 불일치 | 해당 행 스킵 또는 전체 실패 정책을 명시한다. | 행 번호와 원인을 로그로 남길 수 있어야 한다. |
| 규칙 파일 없음 | File DB 기반 규칙 파일 누락 | 초기화 실패 또는 기본 규칙 사용 여부를 명확히 한다. | 조용한 fallback은 테스트와 운영 장애 분석을 어렵게 한다. |
| 전역 상태 | 세션/필터 결과가 전역 변수에 저장됨 | 요청 간 데이터가 섞이지 않아야 한다. | 테스트 간 상태 초기화가 가능해야 한다. |
| 0건 시각화 | 분석 대상 없음 | 0%, 0건으로 표시하고 크래시하지 않는다. | 백분율 계산에서 divide-by-zero를 방지한다. |
| 예외 처리 | 파싱, 파일, 렌더링 중 예외 발생 | 사용자에게 안정적인 오류 응답을 반환하고 내부 상태를 보존한다. | `catch(...)` 남발 대신 구체 예외와 오류 타입을 사용한다. |

## 4. Google Test 기준 테스트 시나리오 목록

1. `TextAnalyzer`는 빈 문자열 입력을 중립 또는 정책상 입력 오류로 일관 처리한다.
2. `TextAnalyzer`는 공백과 개행만 있는 입력을 빈 문자열과 동일하게 처리한다.
3. `TextAnalyzer`는 긍정 키워드가 포함된 피드백을 긍정으로 분류한다.
4. `TextAnalyzer`는 부정 키워드가 포함된 피드백을 부정으로 분류한다.
5. `TextAnalyzer`는 키워드가 없는 피드백을 중립으로 분류한다.
6. `TextAnalyzer`는 키워드가 문자열 맨 앞에 있을 때도 `find() != npos` 기준으로 정상 탐지한다.
7. `TextAnalyzer`는 긍정과 부정 키워드가 동시에 포함된 입력을 명시된 우선순위 정책대로 분류한다.
8. `TextAnalyzer`는 한글, 영문, 숫자, 특수문자가 섞인 입력에서도 예외 없이 결과를 반환한다.
9. `TextAnalyzer`는 대소문자 정책에 따라 `"Delay"`, `"delay"`, `"DELAY"`를 일관 처리한다.
10. `CategoryClassifier`는 배송 관련 키워드가 포함된 피드백을 배송 카테고리로 분류한다.
11. `CategoryClassifier`는 가격 관련 키워드가 포함된 피드백을 가격 카테고리로 분류한다.
12. `CategoryClassifier`는 여러 카테고리 키워드가 동시에 포함된 입력을 정책대로 단일 또는 다중 분류한다.
13. `CategoryClassifier`는 키워드가 없는 입력을 미분류 또는 기타 카테고리로 처리한다.
14. `KeywordMatcher`는 키워드가 문자열 첫 위치에 있을 때 true를 반환한다.
15. `KeywordMatcher`는 키워드가 없을 때 false를 반환한다.
16. `KeywordMatcher`는 빈 키워드 목록을 전달받아도 false 또는 정책상 오류를 안정적으로 반환한다.
17. `Filters`는 긍정 감정 필터 적용 시 긍정 피드백만 반환한다.
18. `Filters`는 부정 감정 필터 적용 시 부정 피드백만 반환한다.
19. `Filters`는 중립 감정 필터 적용 시 중립 피드백만 반환한다.
20. `Filters`는 존재하지 않는 감정 문자열 입력을 오류 또는 빈 결과로 일관 처리한다.
21. `Filters`는 키워드 검색어가 결과 문자열 맨 앞에 있어도 해당 피드백을 반환한다.
22. `Filters`는 빈 검색어 입력 시 전체 반환 또는 입력 오류 중 정의된 정책을 따른다.
23. `Filters`는 분석 로직과 동일한 키워드 매칭 기준을 사용한다.
24. `CsvParser`는 `text` 헤더가 있는 정상 CSV에서 모든 피드백 텍스트를 추출한다.
25. `CsvParser`는 `text` 헤더가 없을 때 명확한 실패 결과를 반환한다.
26. `CsvParser`는 빈 파일 또는 헤더만 있는 파일을 크래시 없이 처리한다.
27. `CsvParser`는 쉼표가 포함된 quoted field를 하나의 텍스트 값으로 파싱한다.
28. `CsvParser`는 따옴표와 개행이 포함된 field를 정책대로 파싱하거나 오류 처리한다.
29. `CsvExporter`는 분석 결과를 고정된 헤더 순서로 출력한다.
30. `CsvExporter`는 쉼표, 따옴표, 개행이 포함된 텍스트를 CSV 규칙에 맞게 escaping한다.
31. `StatisticsCalculator`는 총 0건일 때 비율 계산에서 0으로 나누지 않는다.
32. `StatisticsCalculator`는 긍정/중립/부정 건수 합계가 전체 피드백 수와 일치하도록 계산한다.
33. `StatisticsCalculator`는 반올림 후 표시 비율이 허용 오차 내에서 일관적인지 검증한다.
34. `HtmlRenderer` 또는 Boundary 계층은 사용자 텍스트의 HTML 특수문자를 escaping한다.
35. `HtmlRenderer`는 빈 분석 결과를 0건 상태로 렌더링한다.
36. `Session` 또는 상태 객체는 테스트 간 상태가 누적되지 않도록 초기화 가능해야 한다.
37. `Logger`는 warning 레벨 설정 시 warning 이상 로그만 출력한다.
38. `Logger`는 error 레벨 설정 시 error 로그만 출력한다.
39. `RuleRepository`는 규칙 파일이 없을 때 정의된 오류 결과를 반환한다.
40. `RuleRepository`는 중복 규칙과 빈 규칙을 검증하고 예측 가능한 결과를 반환한다.
41. `TrendAnalyzer`는 날짜별 피드백 수를 집계한다.
42. `TrendAnalyzer`는 정렬되지 않은 입력 데이터를 날짜순 결과로 반환한다.
43. `TrendAnalyzer`는 날짜가 누락된 행을 정책대로 스킵하거나 오류 처리한다.
44. HTTP 라우팅 테스트는 루트 경로 접근 시 대시보드 HTML을 반환하는지 확인한다.
45. HTTP 라우팅 테스트는 피드백 제출 요청이 분석 결과를 생성하고 상태를 갱신하는지 확인한다.
46. HTTP 라우팅 테스트는 CSV 업로드 실패 시 사용자 친화적인 오류 응답을 반환하는지 확인한다.
47. Approval Test는 HTML 출력 계약이 의도치 않게 변경되지 않았는지 검증한다.
48. Approval Test는 CSV 다운로드 출력 계약이 의도치 않게 변경되지 않았는지 검증한다.
49. Approval Test는 JSON 또는 내부 API 응답 계약이 존재할 경우 필드명과 값 형식을 고정한다.
50. 회귀 테스트는 기존 오류 항목인 중립 감정 필터가 올바르게 동작하는지 별도 케이스로 고정한다.

## 5. 테스트 작성 기준

| 기준 | 내용 |
|---|---|
| 테스트 프레임워크 | Google Test 기반 단위 테스트를 기본으로 한다. |
| 테스트 구조 | Given-When-Then 주석 구조를 사용해 준비, 실행, 검증 단계를 분리한다. |
| 우선순위 | 문자열 매칭, 감정 필터, CSV 파싱, 0건 통계, HTML/CSV escaping을 최우선 회귀 테스트로 둔다. |
| 테스트 대상 분리 | Entity/Domain 로직은 HTTP, 파일 시스템, UI 없이 순수 함수 또는 작은 객체로 테스트한다. |
| 출력 계약 | HTML, CSV, JSON 출력은 Approval Test로 변경 여부를 명시적으로 승인한다. |
| 커버리지 목표 | Domain 라인 커버리지 95%, 분기 커버리지 90%, Boundary 90%, Data 85%를 목표로 한다. |
| 상태 격리 | 전역 상태를 사용하는 기존 코드는 각 테스트 전후 초기화하거나 상태 객체로 치환한다. |
| 실패 메시지 | 감정/카테고리/필터 결과는 기대값과 실제값을 명확히 보여주는 assertion을 사용한다. |
