# Feedback Analyzer 테스트 계획서

## 1. 테스트 대상 샘플 예제

### 선택한 기능 이름

텍스트 피드백 입력 기반 감정 분석 및 키워드 분류

### 입력 예시

| 구분 | 입력 |
| --- | --- |
| 정상 입력 | `배송이 너무 늦어요. 화가 납니다.` |
| 경계값 입력 | `배송` |

### 기대 출력

| 구분 | 기대 감정 | 기대 카테고리 |
| --- | --- | --- |
| 정상 입력 | 부정 | 배송 |
| 경계값 입력 | 중립 | 배송 |

### 예제 선택 이유

이 예제는 요구사항에 명시된 핵심 기능인 텍스트 피드백 입력, 키워드 기반 분류, 감정 분석을 한 번에 검증할 수 있다.
문장 형태의 정상 입력과 최소 키워드만 포함한 경계값 입력을 함께 다룰 수 있어 단위 테스트와 회귀 테스트의 기준 사례로 적합하다.

## 2. 테스트 목표

- `TextAnalyzer`의 감정 분석 규칙이 긍정, 부정, 중립을 일관되게 판정하는지 검증한다.
- 키워드 기반 카테고리 분류가 배송 관련 표현을 정확히 탐지하는지 검증한다.
- 필터링, CSV 출력, HTML/JSON 응답 등 Boundary 계층의 출력 계약을 Approval Test로 고정한다.
- 리팩토링 과정에서 도메인 규칙과 입출력 계약이 변경되지 않도록 Google Test와 CTest 기반 회귀 테스트를 구성한다.

## 3. GoogleTest 기반 단위 테스트 범위/우선순위

| 우선순위 | 테스트 범위 | 대상 예시 | 검증 내용 |
| --- | --- | --- | --- |
| P0 | 감정 분석 도메인 규칙 | `TextAnalyzer` | 부정 키워드 포함 문장을 부정으로 판정 |
| P0 | 카테고리 분류 도메인 규칙 | `TextAnalyzer`, `Constants` | `배송` 키워드를 배송 카테고리로 분류 |
| P0 | 중립 판정 규칙 | `TextAnalyzer` | 감정 키워드가 없는 입력을 중립으로 판정 |
| P1 | 필터링 규칙 | `Filters` | 감정/키워드 조건에 맞는 피드백만 반환 |
| P1 | CSV 입력 처리 | `CsvParser` 또는 `FileHandler` 리팩토링 대상 | `text` 필수 컬럼을 기준으로 피드백 목록 생성 |
| P1 | CSV 출력 계약 | 다운로드 기능 | 분석 결과의 컬럼 순서와 값 보존 |
| P2 | UI 출력 계약 | `UIComponents`, HTML 렌더링 | 분석 결과 테이블과 통계 영역의 주요 마크업 유지 |
| P2 | 세션 상태 관리 | `Session` | 입력, 분석 결과, 필터 조건의 상태 격리 |

## 4. 경계값 케이스 목록

| ID | 케이스 | 입력 | 기대 결과 |
| --- | --- | --- | --- |
| B-01 | 최소 유효 키워드 | `배송` | 감정은 중립, 카테고리는 배송 |
| B-02 | 감정 키워드만 존재 | `화가 납니다` | 감정은 부정, 카테고리는 미분류 또는 기본값 |
| B-03 | 카테고리 키워드와 부정 키워드 포함 | `배송이 너무 늦어요. 화가 납니다.` | 감정은 부정, 카테고리는 배송 |
| B-04 | 빈 문자열 | `` | 감정은 중립 또는 입력 오류, 카테고리는 미분류 |
| B-05 | 공백 문자열 | `   ` | 빈 입력과 동일하게 처리 |
| B-06 | 줄바꿈 포함 입력 | `배송이\n늦어요` | 멀티라인 입력을 하나의 피드백으로 분석 |
| B-07 | 매우 긴 입력 | 배송 관련 문장을 반복한 긴 텍스트 | 성능 저하 없이 배송 카테고리 판정 |
| B-08 | 대소문자 혼합 영문 입력 | `Delivery is late` | 영문 키워드 지원 여부에 따라 배송 또는 미분류 |
| B-09 | 중복 키워드 포함 | `배송 배송 배송 늦어요` | 중복 키워드로 인해 중복 카운트 오류가 발생하지 않음 |
| B-10 | 서로 다른 감정 키워드 혼재 | `좋지만 배송이 늦어서 화가 납니다` | 우선순위 규칙에 따라 감정이 결정됨 |

## 5. 예외/특이 케이스 목록

| ID | 케이스 | 기대 처리 |
| --- | --- | --- |
| E-01 | CSV에 `text` 컬럼이 없음 | 업로드 실패 또는 명확한 오류 메시지 반환 |
| E-02 | CSV의 `text` 값이 비어 있음 | 해당 행 제외 또는 중립/미분류 처리 |
| E-03 | CSV 인코딩 문제 | 서버가 중단되지 않고 오류 로그 또는 사용자 메시지 제공 |
| E-04 | HTML 특수문자 포함 입력 | `<script>` 등 입력이 렌더링 시 이스케이프됨 |
| E-05 | 쉼표, 따옴표 포함 CSV 입력 | CSV 파싱 규칙에 따라 하나의 텍스트 필드로 유지 |
| E-06 | 감정 필터 `중립` 선택 | 중립 피드백만 반환하며 긍정/부정 데이터가 섞이지 않음 |
| E-07 | 키워드 검색 결과 없음 | 빈 결과 상태를 정상적으로 표시 |
| E-08 | 동시에 여러 피드백 입력 | 각 피드백의 감정과 카테고리가 독립적으로 계산됨 |
| E-09 | 파일 업로드 실패 | 예외가 전파되어 서버가 종료되지 않음 |
| E-10 | 분석 결과 다운로드 대상 없음 | 빈 CSV 또는 사용자 안내 메시지를 반환 |

## 6. Approval Test 적용 범위

Approval Test는 리팩토링 중 출력 계약이 의도치 않게 변경되는지 확인하기 위해 사용한다.

| 대상 | 승인 기준 |
| --- | --- |
| HTML 분석 결과 페이지 | 주요 섹션, 테이블 헤더, 감정/카테고리 표시 유지 |
| CSV 다운로드 결과 | 컬럼명, 컬럼 순서, 줄바꿈, 분석 결과 값 유지 |
| JSON 응답이 도입될 경우 | 필드명, 타입, 필수 필드 존재 여부 유지 |
| 오류 응답 | 사용자에게 노출되는 오류 메시지와 상태 코드 유지 |

## 7. 커버리지 목표

| 영역 | 목표 | 주요 대상 |
| --- | --- | --- |
| Domain | 라인 커버리지 95% 이상, 분기 커버리지 90% 이상 | `TextAnalyzer`, `Feedback`, 감정/카테고리 규칙 |
| Boundary | 라인 커버리지 85% 이상 | CSV 입출력, HTTP 요청 검증, HTML/CSV 변환 |
| Control | 라인 커버리지 80% 이상 | 분석 흐름, 필터 적용 흐름, 세션 연결 |
| Data | 라인 커버리지 85% 이상 | CSV 파싱, 결과 저장 구조, 상태 객체 |

## 8. gcov / lcov / CTest 측정 전략

### 빌드 설정

- Debug 빌드에서 커버리지 전용 옵션을 활성화한다.
- GCC 또는 Clang 기반 빌드에서 `--coverage`, `-O0`, `-g` 옵션을 적용한다.
- 테스트 실행은 CTest로 통합하여 단위 테스트와 Approval Test를 동일한 파이프라인에서 실행한다.

### 실행 흐름

1. 커버리지 산출물을 초기화한다.
2. CMake로 테스트 빌드를 생성한다.
3. CTest로 전체 테스트를 실행한다.
4. gcov/lcov로 `.gcda`, `.gcno` 데이터를 수집한다.
5. Domain, Boundary 디렉터리 또는 대상 파일별 커버리지 리포트를 분리해 확인한다.
6. HTML 리포트를 생성하여 커버리지 미달 파일과 미검증 분기를 리뷰한다.

### 측정 기준

| 측정 항목 | 기준 |
| --- | --- |
| 라인 커버리지 | 핵심 도메인 로직의 실행 여부 확인 |
| 분기 커버리지 | 긍정/부정/중립, 카테고리 매칭/미매칭, 오류 처리 분기 확인 |
| 함수 커버리지 | 리팩토링 후 사용되지 않는 함수와 죽은 코드 식별 |
| 파일별 커버리지 | Domain 95% 이상, Boundary 85% 이상 기준 충족 여부 확인 |

### 리포트 운영 방식

- PR 또는 리팩토링 단계마다 CTest 결과와 lcov HTML 리포트를 함께 확인한다.
- Domain 커버리지가 95% 미만이면 감정 분석, 키워드 분류, 피드백 모델 테스트를 우선 보강한다.
- Boundary 커버리지가 85% 미만이면 CSV 파싱, 입력 검증, 출력 변환 테스트를 우선 보강한다.
- Approval Test 실패는 출력 계약 변경 여부를 검토한 뒤, 의도된 변경일 때만 승인 파일을 갱신한다.

## 9. 테스트 완료 기준

- P0 테스트가 모두 통과한다.
- 샘플 예제의 정상 입력과 경계값 입력이 기대 출력과 일치한다.
- Domain 커버리지 95% 이상, Boundary 커버리지 85% 이상을 만족한다.
- CTest 실행 결과 실패 테스트가 없다.
- Approval Test 결과에서 의도하지 않은 HTML, CSV, JSON 출력 변경이 없다.
